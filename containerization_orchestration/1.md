Here’s a list of 100 scenario-based questions on containerization and orchestration, tailored for a DevOps engineer. Each question is followed by a one-liner answer.

### Simple Scenario-Based Questions

1. **Scenario:** You need to containerize a Python web application to ensure it works across development, staging, and production environments.
   - **Question:** How would you containerize a Python web application for cross-environment portability?
   - **Answer:** Use a `Dockerfile` to create a Python image, specifying dependencies, environment variables, and the command to run the application.

2. **Scenario:** You have a containerized backend API and a frontend service, and they need to run together.
   - **Question:** How would you use Docker Compose to manage both services running together?
   - **Answer:** Define both services (backend API and frontend) in a `docker-compose.yml` file and link them with networks.

3. **Scenario:** Your containerized application is getting inconsistent results across environments due to dependency differences.
   - **Question:** How would you ensure consistent dependency management in a containerized application?
   - **Answer:** Use a `Dockerfile` with explicit dependency versions and create reproducible environments using multi-stage builds.

4. **Scenario:** Your web app container is losing data after being restarted.
   - **Question:** How would you persist data in Docker to prevent data loss after container restart?
   - **Answer:** Use Docker volumes to mount persistent storage outside the container filesystem.

5. **Scenario:** You want to scale your containerized application to handle more traffic in a Docker Swarm cluster.
   - **Question:** How would you scale a containerized app in Docker Swarm?
   - **Answer:** Use `docker service scale <service_name>=<desired_replica_count>` to scale the service.

6. **Scenario:** You need to expose a container’s port to be accessed by an external system.
   - **Question:** How would you expose a Docker container’s port to the host machine?
   - **Answer:** Use the `-p` option when running `docker run` to map the container’s port to a host port.

7. **Scenario:** A containerized application crashes and you want to ensure it restarts automatically.
   - **Question:** How would you ensure a Docker container restarts automatically if it crashes?
   - **Answer:** Set the `--restart=always` policy when running the container to automatically restart it on failure.

8. **Scenario:** You want to monitor a running container’s logs in real-time for debugging.
   - **Question:** How would you view the logs of a running Docker container?
   - **Answer:** Use the `docker logs -f <container_name>` command to tail the logs.

9. **Scenario:** You need to update a running container with a new Docker image.
   - **Question:** How would you update a running container in Docker?
   - **Answer:** Pull the new image and run `docker-compose up -d` or `docker service update` to apply the changes.

10. **Scenario:** You need to pass environment variables to a containerized application.
   - **Question:** How would you pass environment variables to a Docker container?
   - **Answer:** Use the `-e` flag with `docker run` to specify environment variables.

### Medium Scenario-Based Questions

11. **Scenario:** You want to manage a multi-container web application with a frontend, backend, and database.
   - **Question:** How would you define and deploy a multi-container web application using Docker Compose?
   - **Answer:** Define the frontend, backend, and database services in a `docker-compose.yml` file with their respective images and configurations.

12. **Scenario:** Your Kubernetes pod is not starting due to insufficient resources.
   - **Question:** How would you configure resource requests and limits for a Kubernetes pod?
   - **Answer:** Use `resources.requests` and `resources.limits` in the pod specification to allocate CPU and memory.

13. **Scenario:** Your application needs to be exposed to external users via Kubernetes, but it’s only accessible internally.
   - **Question:** How would you expose a service in Kubernetes to external traffic?
   - **Answer:** Use a `Service` of type `LoadBalancer` or `NodePort` to expose the application to external traffic.

14. **Scenario:** You need to ensure that Kubernetes pods restart only when required, not on every deployment.
   - **Question:** How would you configure a rolling update in Kubernetes to avoid unnecessary restarts?
   - **Answer:** Use `kubectl set image` for rolling updates and set `maxUnavailable` to control the number of pods that can be unavailable during the update.

15. **Scenario:** You need to scale a stateless application across multiple nodes in a Kubernetes cluster.
   - **Question:** How would you scale a Kubernetes deployment across multiple nodes?
   - **Answer:** Use `kubectl scale deployment <deployment_name> --replicas=<desired_count>` to scale the deployment horizontally.

16. **Scenario:** You are using Kubernetes, and you want to ensure that a pod is only scheduled on nodes with specific resources (e.g., GPU).
   - **Question:** How would you restrict a pod to a node with a specific resource in Kubernetes?
   - **Answer:** Use node affinity in the pod specification, such as `nodeSelector` or `affinity`.

17. **Scenario:** Your company uses a microservices architecture, and you need to deploy it in Kubernetes with inter-service communication.
   - **Question:** How would you implement service discovery and communication between microservices in Kubernetes?
   - **Answer:** Use Kubernetes Services with DNS-based service discovery to allow communication between microservices.

18. **Scenario:** You want to deploy a database with persistent storage in Kubernetes, but the database pod needs to retain data across pod restarts.
   - **Question:** How would you set up persistent storage for a database in Kubernetes?
   - **Answer:** Use `PersistentVolume` (PV) and `PersistentVolumeClaim` (PVC) to ensure data persists beyond pod restarts.

19. **Scenario:** You need to deploy an application in Kubernetes that can handle a surge of traffic but automatically scale down when traffic decreases.
   - **Question:** How would you set up Horizontal Pod Autoscaling in Kubernetes?
   - **Answer:** Use the `HorizontalPodAutoscaler` resource to scale pods based on metrics like CPU or memory usage.

20. **Scenario:** You need to set up logging for your application running in Kubernetes, so you can aggregate logs from all pods.
   - **Question:** How would you aggregate logs in a Kubernetes environment?
   - **Answer:** Use a logging solution like Fluentd, Elasticsearch, and Kibana (EFK) stack to collect and visualize logs.

### Complex Scenario-Based Questions

21. **Scenario:** You need to migrate a monolithic application to a microservices architecture running in Kubernetes while ensuring zero downtime.
   - **Question:** How would you handle zero-downtime migration from a monolithic to a microservices-based architecture in Kubernetes?
   - **Answer:** Use a rolling deployment strategy with canary releases in Kubernetes to migrate services without downtime.

22. **Scenario:** Your application in Docker needs to be deployed on multiple cloud platforms with a unified orchestration system.
   - **Question:** How would you deploy a Dockerized application across multiple cloud providers using Kubernetes?
   - **Answer:** Set up a multi-cloud Kubernetes cluster using tools like Rancher or Google Anthos for cross-cloud management.

23. **Scenario:** Your Kubernetes cluster is running multiple namespaces, and you need to isolate traffic between these namespaces.
   - **Question:** How would you implement network isolation between namespaces in Kubernetes?
   - **Answer:** Use Kubernetes Network Policies to control traffic between pods in different namespaces.

24. **Scenario:** You need to manage secrets (API keys, database credentials) securely across your containerized applications.
   - **Question:** How would you securely manage secrets in a Kubernetes environment?
   - **Answer:** Use Kubernetes Secrets to store sensitive data and mount them into pods as environment variables or volumes.

25. **Scenario:** You are managing a large-scale Kubernetes deployment and need to ensure that a pod only runs on a node that has enough available resources.
   - **Question:** How would you configure pod scheduling in Kubernetes to ensure resource constraints?
   - **Answer:** Use `resource requests` and `limits` along with `nodeSelector` or `affinity` to ensure proper resource allocation.

26. **Scenario:** Your containerized application is being deployed through a CI/CD pipeline, and you want to automate the process of testing and pushing Docker images.
   - **Question:** How would you automate the testing and pushing of Docker images in a CI/CD pipeline?
   - **Answer:** Use Jenkins, GitLab CI, or GitHub Actions with Docker build and push steps as part of the pipeline.

27. **Scenario:** You need to handle traffic routing between different versions of an application in Kubernetes.
   - **Question:** How would you implement traffic routing for canary deployments in Kubernetes?
   - **Answer:** Use Kubernetes Ingress with weighted routing to distribute traffic between different versions of the app.

28. **Scenario:** Your company wants to ensure that containers are scanned for vulnerabilities before they are deployed to production.
   - **Question:** How would you implement automated vulnerability scanning for Docker images?
   - **Answer:** Integrate tools like Clair, Trivy, or Anchore into your CI/CD pipeline to scan Docker images before deployment.

29. **Scenario:** You need to optimize the cost of running containers in a cloud environment with Kubernetes.
   - **Question:** How would you optimize Kubernetes for cost-efficient container orchestration in the cloud?
   - **Answer:** Use autoscaling for both the Kubernetes nodes and pods, and utilize spot instances for cost savings.

30. **Scenario:** Your application is experiencing slow response times, and you suspect resource contention in Kubernetes.
   - **Question:** How would you investigate and resolve resource contention issues in Kubernetes?
   - **Answer:** Use `kubectl top pod` to monitor resource usage, and adjust pod `requests` and `limits` to balance resource allocation.

### More Complex Scenario-Based Questions

31. **Scenario:** You are deploying a microservices application across multiple Kubernetes clusters located in different regions for disaster recovery.
   - **Question:** How would you set up multi-region Kubernetes clusters for disaster recovery?
   - **Answer:** Use tools like Rancher or Federation to manage multiple Kubernetes clusters across regions for high availability.

32. **Scenario:** Your team needs to monitor the health of a Kubernetes cluster running critical production workloads.
   - **Question:** How would you set up health checks (liveness and readiness probes) for production workloads in Kubernetes?
   - **Answer:** Configure `livenessProbe` and `readinessProbe` in the pod specification to automatically detect and recover from application failures.

33. **Scenario:** Your application needs to scale based on custom metrics (e.g., number of active users).
   - **Question:** How would you implement custom metric-based scaling in Kubernetes?
   - **Answer:** Set up custom metrics using the Kubernetes Metrics Server and configure Horizontal Pod Autoscalers to scale based on these metrics.

34. **Scenario:** You need to configure an application in Kubernetes to ensure that no service is exposed until it has been fully initialized and is ready to handle traffic.
   - **Question:** How would you implement a pre-traffic initialization check in Kubernetes?
   - **Answer:** Use the `readinessProbe` to ensure services are only exposed when they are fully initialized and ready.

35. **Scenario:** Your Docker containers are part of a microservice architecture and need to communicate securely across services.
   - **Question:** How would you secure communication between Docker containers in a microservice architecture?
   - **Answer:** Use service mesh solutions like Istio or Linkerd to manage secure communication between containers via mutual TLS.

36. **Scenario:** You need to ensure that each container in a multi-container environment can access and log into a specific database service.
   - **Question:** How would you set up inter-container communication with a shared database service in Docker Compose?
   - **Answer:** Define the database service in the `docker-compose.yml` file and configure the backend containers to link to it through environment variables.

37. **Scenario:** Your team is implementing a CI/CD pipeline with Kubernetes, and you need to roll back a deployment due to a failure in the new version.
   - **Question:** How would you perform a rollback in Kubernetes after a failed deployment?
   - **Answer:** Use `kubectl rollout undo deployment <deployment_name>` to roll back to the previous version of the deployment.

38. **Scenario:** You are deploying a Kubernetes workload with a limited number of nodes and want to ensure that resource-intensive applications are scheduled efficiently.
   - **Question:** How would you schedule high-priority workloads on specific nodes in Kubernetes?
   - **Answer:** Use `taints` and `tolerations` to ensure that specific workloads are scheduled only on appropriate nodes.

39. **Scenario:** You need to upgrade a Kubernetes cluster, but you want to ensure minimal disruption to the running services.
   - **Question:** How would you upgrade a Kubernetes cluster with minimal downtime?
   - **Answer:** Perform a rolling upgrade using `kubeadm` or your cloud provider’s upgrade tool, ensuring nodes are upgraded one at a time.

40. **Scenario:** Your organization needs to comply with industry regulations regarding container security, and you need to ensure that all containers meet these standards.
   - **Question:** How would you enforce security policies for Docker containers in a regulated environment?
   - **Answer:** Use tools like Docker Content Trust (DCT), Kubernetes PodSecurityPolicies, or third-party solutions like Aqua or Sysdig to enforce security standards.
