#### **Terraform**

29. **Scenario:** You are managing infrastructure for a multi-region application using Terraform and need to ensure that the network configuration is consistent across all regions.
   - **Question:** How would you ensure a consistent network configuration across multiple AWS regions in Terraform?
   - **Answer:** Define a `provider` block for each region and use `count` or `for_each` to create the network resources (e.g., VPCs, subnets) across multiple regions, ensuring consistency by parameterizing values.

30. **Scenario:** You have a stateful application running on AWS EC2 instances, and you want to use Terraform to create an Auto Scaling group for high availability.
   - **Question:** How would you create an Auto Scaling group in Terraform for a stateful application on AWS?
   - **Answer:** Use `aws_autoscaling_group` along with `aws_launch_configuration` or `aws_launch_template` in Terraform to define the Auto Scaling group, and attach it to the appropriate load balancer to ensure high availability.

31. **Scenario:** Your Terraform scripts require sensitive access credentials that need to be managed securely across multiple environments.
   - **Question:** How would you securely manage sensitive credentials in Terraform for different environments?
   - **Answer:** Use Terraform's `vault` provider to fetch sensitive data from HashiCorp Vault or store credentials in encrypted files or environment variables, ensuring the `sensitive = true` flag is set for any sensitive outputs.

32. **Scenario:** You want to reuse existing Terraform modules to avoid redundancy but need to pass different configurations to each module based on the environment.
   - **Question:** How would you reuse Terraform modules with different configurations for each environment?
   - **Answer:** Use Terraform’s `module` block, pass environment-specific variables (e.g., `dev`, `staging`, `prod`) through the `vars` argument, and create separate workspaces to manage environment-specific state.

33. **Scenario:** Your Terraform deployment is failing due to missing permissions for creating certain resources on AWS. You need to debug and resolve the permission issue.
   - **Question:** How would you debug and resolve missing permissions issues in Terraform on AWS?
   - **Answer:** Check the IAM policy attached to the Terraform execution role, ensure that it includes the necessary permissions for the resources being created, and review the error message for missing resource-specific actions.

#### **Ansible**

34. **Scenario:** You are deploying a multi-tier application, where the database, application server, and load balancer need to be configured in a specific order.
   - **Question:** How would you define the correct execution order for configuring a multi-tier application in Ansible?
   - **Answer:** Use Ansible’s `roles` to group tasks by tier, and set `depends_on` in roles or use `pre_tasks` and `post_tasks` to define the correct execution order between the database, application, and load balancer configurations.

35. **Scenario:** You need to configure multiple servers with different software versions based on the server's role (e.g., web server vs. database server).
   - **Question:** How would you configure servers with different software versions using Ansible based on their role?
   - **Answer:** Use Ansible inventories to define server roles, then conditionally apply the correct software versions in your playbooks by checking the host's role or using `when` statements based on inventory variables.

36. **Scenario:** Ansible playbooks run successfully but with a delay due to waiting for SSH connections. You need to improve the execution speed.
   - **Question:** How would you improve the speed of Ansible playbook execution when facing SSH connection delays?
   - **Answer:** Use Ansible's `async` feature for long-running tasks, increase the `forks` parameter in your `ansible.cfg` to run more tasks concurrently, and optimize SSH configurations to reduce connection latency.

37. **Scenario:** You are tasked with patching a fleet of servers using Ansible, but you need to ensure the patches don't cause downtime.
   - **Question:** How would you implement zero-downtime patching on multiple servers using Ansible?
   - **Answer:** Use Ansible’s `serial` keyword to patch servers in batches, ensuring that not all servers are patched at once. Additionally, use `service` modules to restart services gracefully after patching to avoid downtime.

38. **Scenario:** Your Ansible playbook requires you to handle server failures gracefully by retrying failed tasks a few times before moving on to the next task.
   - **Question:** How would you implement task retries in Ansible playbooks?
   - **Answer:** Use Ansible’s `retries` and `delay` parameters in task definitions to specify how many times a task should be retried and the delay between retries before marking it as failed.

#### **AWS CloudFormation**

39. **Scenario:** You want to update an existing CloudFormation stack with new parameters, but you don’t want to delete and recreate the entire stack.
   - **Question:** How would you update an existing CloudFormation stack without deleting and recreating it?
   - **Answer:** Use the `aws cloudformation update-stack` command or the CloudFormation Console to modify the stack and apply only the necessary changes, making sure no resources are inadvertently deleted or replaced.

40. **Scenario:** You want to create multiple CloudFormation stacks in a specific order to ensure dependencies are respected.
   - **Question:** How would you manage dependencies between multiple CloudFormation stacks?
   - **Answer:** Use the `AWS::CloudFormation::Stack` resource to reference one stack from another, or use StackSets to deploy resources in a specific order across multiple regions.

41. **Scenario:** You need to ensure that CloudFormation resources are properly tagged with environment-specific values for cost allocation and management.
   - **Question:** How would you enforce consistent resource tagging in CloudFormation?
   - **Answer:** Use the `Tags` property within CloudFormation resources to enforce consistent tagging or implement custom AWS Lambda-backed custom resources to enforce tags at creation.

42. **Scenario:** Your CloudFormation stack failed to create due to a resource conflict. You need to resolve the conflict and retry the deployment.
   - **Question:** How would you resolve a resource conflict and retry a failed CloudFormation stack creation?
   - **Answer:** Review the CloudFormation stack events to identify the specific resource conflict, resolve it (e.g., adjust resource names or properties), and use `aws cloudformation update-stack` to retry the stack creation.

43. **Scenario:** You need to manage a production environment where CloudFormation templates are being shared across teams. You want to enforce strict policy compliance before allowing template updates.
   - **Question:** How would you enforce policy compliance for CloudFormation templates before allowing updates?
   - **Answer:** Use AWS Config with CloudFormation StackSets or third-party tools like CloudFormation Guard to enforce policies and ensure templates meet compliance requirements before deployment.

#### **Pulumi**

44. **Scenario:** You want to use Pulumi to manage cloud resources in both AWS and Azure from a single codebase. The resources should be provisioned based on the selected cloud provider.
   - **Question:** How would you manage resources across multiple cloud providers with Pulumi?
   - **Answer:** Use Pulumi’s multi-provider support, where you define provider-specific configurations (`aws.Provider`, `azure.Provider`) in your code, and pass them dynamically to your resource definitions based on the environment or cloud choice.

45. **Scenario:** Your Pulumi code defines an AWS EC2 instance and an S3 bucket. You want the S3 bucket to be created only after the EC2 instance is successfully provisioned.
   - **Question:** How would you ensure that the S3 bucket is created only after the EC2 instance is provisioned using Pulumi?
   - **Answer:** Use Pulumi’s `dependsOn` argument to define an explicit dependency between the EC2 instance and the S3 bucket, ensuring that the bucket is only created after the EC2 instance.

46. **Scenario:** Your Pulumi infrastructure code is using AWS Lambda functions, and you want to ensure that each function is deployed with the appropriate IAM role and permissions.
   - **Question:** How would you manage IAM roles for AWS Lambda functions using Pulumi?
   - **Answer:** Define an `aws.iam.Role` resource in Pulumi and assign the role to each Lambda function using the `role` property. Ensure the IAM role has the necessary policies for Lambda execution.

47. **Scenario:** You want to automate the process of provisioning a Kubernetes cluster and deploying applications to it using Pulumi, with support for rolling updates.
   - **Question:** How would you automate Kubernetes cluster provisioning and application deployment with rolling updates using Pulumi?
   - **Answer:** Use Pulumi's `@pulumi/kubernetes` package to provision the Kubernetes cluster (e.g., using EKS) and define `Deployment` resources with `RollingUpdate` strategies to ensure zero-downtime updates for your applications.

48. **Scenario:** You need to share common infrastructure components (e.g., networking, storage) across multiple Pulumi projects, ensuring consistency and reusability.
   - **Question:** How would you share common infrastructure components across multiple Pulumi projects?
   - **Answer:** Create reusable Pulumi components as packages or libraries, and import them into multiple projects to ensure common infrastructure components like VPCs or storage are consistently used across environments.

#### **Chef**

49. **Scenario:** You need to deploy a Chef-managed application to a fleet of servers, ensuring that each server is correctly configured based on its environment (e.g., dev, staging, production).
   - **Question:** How would you ensure servers are configured based on their environment in Chef?
   - **Answer:** Use Chef environments and roles to define environment-specific configurations. Apply roles to nodes based on their environment to customize recipes and attributes for each deployment.

50. **Scenario:** Your Chef-managed infrastructure requires updates for several application components. You want to automate the update process with minimal disruption.
   - **Question:** How would you automate application updates with minimal disruption in Chef?
   - **Answer:** Use Chef’s `rolling_update` or `chef-client` with `converge` strategies to update application components in a staggered manner, ensuring that only a small number of nodes are updated at any given time.
