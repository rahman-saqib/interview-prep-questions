#### 36. **Scenario:** You are managing infrastructure for a large-scale web application on AWS.    - **Question:** How would you structure your Terraform configuration to maintain modularity and clear separation of resources for a large-scale web application?
   - **Answer:** Organize your Terraform configuration into multiple modules, with each module responsible for a specific aspect of the infrastructure (e.g., `vpc`, `ec2_instances`, `iam_roles`). Use **`outputs`** from one module to pass values (e.g., VPC ID, security group IDs) to another, ensuring modularity and reusability. This approach enhances maintainability and reduces code duplication.

#### 37. **Scenario:** Your team is responsible for creating highly available, scalable infrastructure on AWS using Terraform. The architecture involves deploying EC2 instances, RDS databases, and an Auto Scaling Group (ASG) across multiple availability zones (AZs).

   - **Question:** How would you design and deploy a highly available infrastructure across multiple AZs using Terraform?
   - **Answer:** Use the **`aws_vpc`** resource to create a VPC with subnets across multiple AZs. Define an **Auto Scaling Group (ASG)** and **launch configurations** for EC2 instances, ensuring that instances are spread across AZs. For RDS, use **Multi-AZ deployments** by setting `multi_az = true` in the `aws_db_instance` resource. This configuration ensures high availability and fault tolerance across the infrastructure.

#### 38. **Scenario:** Your organization requires the automatic provisioning of AWS Lambda functions with the appropriate IAM permissions. The Lambda functions need to be triggered by events from other AWS services (e.g., S3, DynamoDB).

   - **Answer:** Use the **`aws_lambda_function`** resource to define Lambda functions. For IAM roles, use the **`aws_iam_role`** and **`aws_iam_role_policy_attachment`** resources to attach the required policies. For event triggers, use the **`aws_s3_bucket_notification`** or **`aws_dynamodb_table_stream`** to set up event sources that trigger the Lambda function when specific conditions are met.

   - **Answer:** For security groups, use **restrictive rules** that only allow necessary traffic (e.g., limit inbound SSH access to specific IPs).    - **Answer:** Terraform automatically checks for existing resources using **state files**. For resources like EC2 instances or VPCs, you can define **`lifecycle`** rules with the `prevent_destroy` argument to ensure that resources are not accidentally deleted. Additionally, use the **`terraform import`** command to import existing resources into your Terraform state, ensuring that they are managed by Terraform without duplication.
